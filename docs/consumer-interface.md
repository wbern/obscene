# Consumer interface — design doc

**Status**: proposal, not yet implemented (bd `ob-5i4`).
**Scope**: defines the wire formats `obscene` should expose so non-CC consumers
(other agent runners, CI systems, humans) can use it without writing their own
wrapper. **No code lands from this doc directly**; follow-up beads will pick
items off the matrix.

## Problem

`obscene hook` currently emits Claude Code's lifecycle envelope shapes —
`hookSpecificOutput.additionalContext` for context-injecting events,
`systemMessage` for `Stop`/`SubagentStop`/`PreCompact`. This works for CC and
will keep working. It assumes the rest of the world looks like CC, which is
where the risk lives: locking content production around one runner's envelope
shape means every new consumer (Cursor, Codex, Continue, Goose, GitLab CI, the
GitHub Security tab) needs a bespoke wrapper.

The good news: the split already half-exists in `src/hook.ts` —
`formatHotspotDeltaForAgent` returns a plain `string`, and
`buildClaudeHookOutput` is the only CC-coupled wrapper. The content / transport
boundary is sitting right there; this doc proposes how to widen it.

## Findings

### Agent runners cluster into 4 wire-format buckets

| Bucket | Format | Runners covered |
| --- | --- | --- |
| **CC-style JSON envelope** | `{hookSpecificOutput:{additionalContext}}` / `{systemMessage}` | Claude Code, Codex CLI (verbatim — same field names), Cursor (snake_case rename: `additional_context`) |
| **MCP server** | JSON-RPC tools returning `{content:[{type:"text",text}]}` | Goose, OpenCode, Cline, Continue, Cursor MCP, Claude Desktop, Codex MCP — every MCP-capable client for free |
| **HTTP ContextItem** | POST → `{name, description, content}` | Continue.dev custom providers |
| **Plain stdout / markdown** | unstructured text | Aider `/run`, Plandex pipe, Cline workflows, reviewdog stdin, Danger file input, humans |

Observations:
- Codex CLI shipped hooks with **the same field names as Claude Code**
  (`hookSpecificOutput.additionalContext`, `systemMessage`, `decision`,
  `continue`). The current envelope works there unchanged.
- Cursor is one snake_case rename and a wrapper drop away
  (`additional_context` instead of `hookSpecificOutput.additionalContext`).
- Aider / Plandex / Cline-workflows just want text — no envelope at all.
- OpenCode requires an in-process TS plugin, not a stdio contract; out of
  scope for the binary to natively support, but a `plugins/obscene.ts`
  template in `examples/` would cover it.
- Goose's hint surface (`.goosehints`/`AGENTS.md`) is a static file
  regenerated by cron — no live hook contract needed.

### CI surfaces cluster into 5 load-bearing wire formats

| Format | What it powers | Effort |
| --- | --- | --- |
| **SARIF 2.1.0** | GitHub Security tab, Azure DevOps SAST extension, JetBrains Qodana, SonarQube import, VS Code SARIF Viewer | ~150 LOC |
| **GitLab Code Quality JSON** | GitLab MR widget + pipeline Code Quality tab | ~30 LOC |
| **JUnit XML** | Jenkins / GitLab / CircleCI / Azure DevOps "Tests" tabs (cheap blocking gate) | ~50 LOC |
| **GitHub Actions annotations** | inline PR file comments + Checks tab summary | ~20 LOC |
| **reviewdog `errorformat`** | github-pr-check, gitlab-mr-discussion, gerrit-change-review, bitbucket-code-report — all PR-comment surfaces via one external tool | ~10 LOC |

Notably:
- **There is no standardized hotspot interchange format.** CodeScene (Tornhill's
  commercial tool) emits no public hotspot JSON schema. SonarQube uses its
  proprietary Generic Issue format. Greenfield: emitting SARIF + GitLab CQ +
  JUnit covers ~95% of CI surfaces.
- GitHub PR-comment posting (with marker-based upsert, 65,536-char truncation,
  fork-PR proxying, concurrency races) is a solved problem owned by
  `mshick/add-pr-comment` and `thollander/actions-comment-pull-request`. We
  should **not own this** — emit markdown, let the action upload it.
- Danger plugin same pattern: ~30 LOC of TS reading our `--json`. Should live
  in a separate `danger-plugin-obscene` repo, not in core.
- OSV schema, Codecov coverage formats: semantically wrong for us. Skip.

### Exit-code idioms (from static-analysis prior art)

Three settled patterns:

1. **Informational, always 0** (radon, scc, our current default). Reporting
   tool; gates are layered externally (xenon for radon).
2. **Findings-fail with suppression flag** (lizard, flake8, ruff, semgrep).
   Non-zero when anything triggers; `--exit-zero` / `--max-warnings N` to
   downgrade. This is the modern default.
3. **Bitmask by severity** (pylint). Universally regretted — `pylint-exit`
   exists because the bitmask is unmanageable. **Do not imitate.**

A hotspot is inherently advisory ("this file is risky"), not a failure ("you
broke something"). The right shape is **(1) by default + opt-in `--fail-on`
gate** (ruff/eslint style): `--fail-on-tier HOT`, `--fail-on-count 5`,
`--fail-on-score 80`. Separate the gate flag from the output format flag so
"emit SARIF" and "fail the build" are independent.

### Streaming

Only Code Climate engines and `scc --format csv-stream` actually stream.
SARIF, GitLab CQ, JUnit are all one-shot documents. Our output sizes are
small (tens of files, not millions of LOC). **One-shot is correct.** Don't
build streaming.

### Schema stability lessons

- SARIF and GitLab Code Quality are formally versioned with public JSON
  schemas — safe to bind to.
- Native JSON from radon, lizard, scc, complexity-report is best-effort,
  ad-hoc, sometimes breaks across minor versions. Lesson: if we ship a
  canonical `obscene` JSON, **version it explicitly** (e.g.
  `"schemaVersion": "1.0"` at the top) and document deprecation policy.
- flake8 issue #180 (tool failure exits 0): **separate "tool failure" from
  "no findings"** in our exit code. Reserve exit 2 for operational errors.

## Proposed API surface

### Four abstraction axes

| Axis | Values | How it surfaces |
| --- | --- | --- |
| **Output format** | `json` (canonical), `table` (current default), `compact`, `markdown`, `sarif`, `gitlab-codequality`, `junit`, `gh-actions`, `errorformat` | `--format <name>` (existing flag, broadened) |
| **Exit-code mode** | informational (default), fail-on-tier, fail-on-count, fail-on-score | `--fail-on-{tier,count,score} <n>` (new) |
| **Content variant** | `drift`, `hotspots`, `coupling`, `report`, `landscape` | existing subcommands (no change) |
| **Transport** | stdio (one-shot, default), MCP server (long-running), file via `-o/--output` | existing stdout + new `obscene mcp` subcommand + new `-o` flag (scc-style) |

Streaming is intentionally not an axis — out of scope.

### Decision: what to own, defer, or skip

**Own in core** (ship in `obscene` binary):

| Item | Reach gained | Rationale |
| --- | --- | --- |
| `--format json` with `"schemaVersion"` field | foundation — every other format converts from this | already have JSON; add explicit version |
| `--format sarif` | GitHub Security tab + Azure DevOps + SonarQube import + JetBrains Qodana | one format, four major surfaces |
| `--format gitlab-codequality` | GitLab MR widget | ~30 LOC, single ecosystem but the *only* native path there |
| `--format junit` | Jenkins / GitLab / CircleCI / Azure "Tests" tabs as blocking gates | cheapest path to "blocking on GitLab without writing a plugin" |
| `--format gh-actions` | inline PR annotations on GitHub | ~20 LOC, pairs with SARIF (annotations = "look now", SARIF = "track over time") |
| `--format errorformat` | reviewdog → github-pr-check, gitlab-mr-discussion, gerrit, bitbucket | ~10 LOC, multiplies reach through one external tool |
| `--format cursor` | Cursor sessionStart hook (`additional_context` snake_case, no wrapper) | one rename + drop wrapper, gets a major IDE-agent for free |
| `-o, --output <path>` (and possibly `--format-multi` à la scc) | dev ergonomics — emit table to stdout AND json to file in one run | proven pattern from scc |
| `--fail-on-tier HOT` / `--fail-on-count N` / `--fail-on-score N` | CI gating without parsing output | ruff/eslint idiom, opt-in |
| `obscene mcp` subcommand | MCP server exposing `hotspots`/`drift`/`coupling` tools | one integration unlocks Goose, OpenCode, Cline, Continue, Cursor MCP, Claude Desktop, Codex MCP |
| `.pre-commit-hooks.yaml` manifest | pre-commit framework users (ubiquitous) | one YAML file; `stages: [pre-push]` since analysis is too slow for pre-commit |

**Defer to wrappers/examples** (document the recipe, don't ship the binary):

| Item | Why deferred |
| --- | --- |
| `danger-plugin-obscene` | ~30 LOC TS in a separate repo; not core's job |
| GitHub PR comment posting | `mshick/add-pr-comment` already owns marker upsert, truncation, fork-PR proxying, concurrency. We emit markdown, they post it. |
| HTTP `ContextItem` endpoint for Continue.dev | thin HTTP wrapper around `obscene hotspots --format markdown`; ship as `examples/continue-http-shim/` rather than `obscene serve` |
| OpenCode TS plugin | in-process plugin model; ship `examples/opencode-plugin.ts` template that shells out |
| Goose `.goosehints` generation | static-file pattern; cron + `obscene hotspots --format markdown > .goosehints` |

**Never own:**

| Item | Why |
| --- | --- |
| OSV schema output | vuln-centric semantics; consumers won't render hotspot data |
| Codecov / Coveralls formats | we are not coverage |
| pylint-style bitmask exit codes | universally regretted |
| Streaming output | one-shot suffices for our size |
| PR comment poster binaries | solved problem, multiple battle-tested actions exist |

### Renaming the existing `hook` subcommand

`obscene hook --event Stop` is CC-specific naming. Once `--format` covers
the CC envelope as one option among many, the cleanest re-shape is:

```
obscene drift --base HEAD~1 --format claude-code-hook --event Stop
obscene drift --base HEAD~1 --format cursor --event sessionStart
obscene drift --base HEAD~1 --format markdown
obscene drift --base HEAD~1 --format sarif
```

`hook` becomes a thin alias for backwards compatibility (`obscene hook` →
`obscene drift --format claude-code-hook`). The content-producing function
(`formatHotspotDeltaForAgent` in `src/hook.ts`) doesn't move; only the
transport-layer wrappers expand.

### Suggested rollout order

These are independent and can land in any order, but this sequencing
maximizes early payoff:

1. **`--format json` with `schemaVersion`** — foundation everything else
   converts from. Cheap; unblocks downstream contributors.
2. **`--format sarif`** — biggest single-format reach (GitHub Security tab
   alone is significant). Forces us to settle the "informational vs
   blocking" question with `--fail-on-*` flags.
3. **`--format gh-actions`** + **`--format errorformat`** — both tiny, both
   unlock major PR-review surfaces.
4. **`--format gitlab-codequality`** + **`--format junit`** — covers the
   GitLab MR widget and provides a blocking gate on Jenkins/GitLab/Circle.
5. **`--format cursor`** + the `hook` → `drift --format` rename — picks up
   Cursor for free, cleans up the CC-only naming smell.
6. **`obscene mcp`** subcommand — biggest leverage in the agent-runner
   bucket (one integration → seven runners). Larger lift than the format
   flags, so it goes after the cheaper wins.
7. **`.pre-commit-hooks.yaml`** — one YAML file, document opt-in in README.
8. **Examples directory** — `examples/danger-plugin/`,
   `examples/continue-http-shim/`, `examples/opencode-plugin.ts` —
   templates the community can fork. Not core code.

## Non-goals (preserved from bead spec)

- Not blocking ob-yto (threshold tuning) or ob-6hs (recency window) — both
  shipped before this doc landed.
- Not committing to support every surface; the point is to know what
  exists before locking.
- Not a CC-bashing exercise. CC remains a first-class consumer; the rename
  surfaces it as `--format claude-code-hook`, not as an afterthought.
